
### 1.如何看待传统软件和agent类软件的区别？

传统软件更像是**规则驱动的软件**。开发者提前把流程、按钮、判断条件和结果都写清楚，用户点击什么，系统就按固定逻辑执行什么。
它的优点是稳定、可预测、容易测试，
但缺点是灵活性有限，用户必须按照系统设计好的方式使用。

Agent 类软件更像是**目标驱动的软件**。用户不一定需要一步步操作，而是直接表达目标，比如“帮我分析适合长期持有的美股”。系统会自己拆解任务、选择工具、调用数据、生成结果。
它的优势是更灵活、更接近自然语言交互，也能处理开放性任务；
但它的问题是结果不完全确定，所以更需要权限控制、过程记录、结果校验和人工边界。

结合我的项目来说，传统软件部分是网页、API、数据库、回测、PDF 导出这些确定性模块；Agent 部分是需求理解、研究计划、证据检索、正反分析和报告生成。
我的理解是，Agent 软件不是替代传统软件，而是建立在传统软件之上。传统软件提供稳定的结构和安全边界，Agent 负责处理更开放、更复杂的用户意图。最好的系统应该是两者结合：底层稳定可控，上层智能灵活。

### 2.大模型产品或者agent产品如何解决幻觉问题：
![[Pasted image 20260506162848.png|697]]
**Agent 方向**更偏产品落地。它不直接相信模型的自由回答，而是先让 Agent 去检索资料、调用工具、查询数据库或 API，然后让模型基于这些资料回答。比如 RAG 可以把相关文档找出来，工具调用可以获取真实行情、计算结果或数据库内容，Prompt 约束可以限制模型回答范围，结构化输出可以让系统检查字段是否完整，最后再通过 Validator 或规则校验判断回答和证据是否一致。如果数据不够，就应该明确提示信息不足，而不是硬生成答案。
**模型方向**更偏底层能力提升。比如通过 SFT 让模型学习更符合任务要求的回答方式，通过 RLHF 或 DPO 让模型更符合人类偏好，通过更高质量的训练数据减少错误知识，通过模型架构和解码策略优化减少胡编乱造。这些方法可以从源头降低幻觉概率，但一般需要训练资源，更多是模型厂商或大模型团队做的事情。
