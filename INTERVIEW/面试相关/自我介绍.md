GenAI based Financial agent

- **S (情境)：** 传统金融数据分析门槛极高，普通用户很难通过自然语言直接获得结构化的深度分析。当时市面上的单体大模型处理长链路任务时，往往存在响应慢、容易产生幻觉的问题。
    
- **T (任务)：** 我的目标是构建一个具备“感知-思考-执行”能力的完整 Agent 系统，并且要求它具备**低延迟、高可靠性**，能够真正落地解决用户的复杂查询需求。
    
- **A (行动)：** 在这个项目中，我主导了整体的引擎架构设计，摒弃了低效的单线处理，采用了**微服务并行架构**：
    
    - **意图解析与分发 (感知)：** 设计了前置的意图解析模块，精准捕捉用户的模糊需求。
    - **工具解耦与封装 (Tool Calling)：** 我将复杂的量化计算、外部新闻检索等功能剥离，封装为独立的底层 API 节点。通过标准的 JSON 数据矩阵进行信息交互，极大提升了系统的稳定性。
    - **工作流编排与并行调度 (思考与执行)：** 在 Poffices 引擎中，我设计了从“海选筛选”到“并行执行（同步抓取量价数据与宏观新闻）”，再到“Ranking（重排）”和“Merge（融合）”的完整 Block 工作流。这种并行调度机制大幅缩短了数据处理的等待时间。
- **R & T (结果与 PM 启发)：** 系统成功实现了从“自然语言输入”到“专业结构化决策输出”的闭环，且响应效率和准确度大幅提升。 **💡 (绝杀切入 PM 视角 - 针对韶音的转化)：** “这段经历让我完成了一次从‘单点开发’到‘系统架构与产品经理’的思维跳跃。我深刻理解了如何**将大模型的黑盒能力，拆解成工程上可控、可调用的 API 工作流**。

### 第一步：用户输入与意图解析（感知层）
- **运作逻辑：** 当用户输入一段模糊的自然语言查询（例如：“帮我分析一下最近新能源板块的走势，结合一下宏观政策”），系统并不会直接把这句话扔给大模型，而是先通过一个前置的意图解析模块。
- **产品视角（你的价值）：** 这一步解决了“用户不知道怎么写精确指令”的痛点。系统精准提取用户的真实需求，并将其转化为底层可读的指令，决定接下来需要激活哪些工具链。
### 第二步：海选筛选与路由分发（调度层）
- **运作逻辑：** 系统根据解析出的意图，把一个复杂的宏大任务拆解成多个小任务，并进行路由分发。
- **产品视角（你的价值）：** 这里体现了系统的“解耦思维”。就像是一个项目经理（主控 Agent）把大任务分发给不同的专员（子节点）。各个模块互不干扰，即使一个节点出错，也不会导致整个系统崩溃，极大提升了系统的可靠性。
### 第三步：并行执行与工具调用（执行层 —— 核心技术壁垒）
- **运作逻辑：** 这是整个架构中效率最高的一环。系统会**同时**触发多个底层的能力封装模块（Tool Calling）。例如，一边调用 RPA 抓取模块去获取最新的量价时序数据并进行清洗降噪，另一边同步调用网络搜索 API 抓取实时的宏观财经新闻。
- **产品视角（你的价值）：** 面试时一定要重点强调**“并行（Parallel）”**。传统的大模型是单线思考，极其拖沓。通过并行调用，大幅降低了系统的响应延迟。在向韶音的面试官表达时，可以引申为：“我深知在智能硬件（比如未来的 AI 耳机）中，低延迟是用户体验的生命线，这种并行架构的思维可以直接复用到硬件端的数据处理上。”
### 第四步：Ranking（深度评估与重排）
- **运作逻辑：** 并行抓取回来的数据往往是海量且存在“噪音”的。系统需要对这些复杂数据进行量化特征提取，并根据当前任务的相关性进行打分和重新排序（Ranking），剔除无关的冗余信息。
- **产品视角（你的价值）：** 展现你对数据质量和系统边界的严格把控。这是避免 AI 产生“幻觉”、确保输出结果专业可信的关键步骤。
### 第五步：Merge（融合与决策输出）
- **运作逻辑：** 将所有经过高强度提纯的结构化数据（财务指标、量化特征、高优新闻摘要）统一汇总，交由作为“主脑”的 LLM 进行最终的逻辑推理，最终通过 FastAPI 端点输出决策。
- **产品视角（你的价值）：** 实现了从“原始杂乱数据”到“高价值商业决策”的完美闭环。
